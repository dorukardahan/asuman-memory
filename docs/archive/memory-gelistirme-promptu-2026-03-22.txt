### Hook Dosya Yapısı
Her hook dizini:
hook-name/
├── HOOK.md # Metadata (YAML frontmatter) + docs
├── handler.js # Ana handler (ESM export default)
└── handler.js.example # Örnek/backup

Handler imzası:
const hookHandler = async (event) => {
// event.type: 'command' | 'session' | 'agent' | 'gateway' | 'message'
// event.action: 'new' | 'reset' | 'received' | 'sent' | etc.
// event.sessionKey: string
// event.context.content: string (message:received/sent)
// event.context.from/to: string
// event.context.bootstrapFiles: array (agent:bootstrap)
// event.messages: string[] (push to send messages to user)
};
export default hookHandler;

### Mevcut bootstrap-context handler.js Akışı
1. fetchLessons(agentId) → recall("behavioral lessons corrections mistakes", agent, memoryType: "lesson") — MAX_LESSON_CHARS=3000
2. fetchRecentMemories(agentId, namespace) → 5 farklı query (recent events, decisions, feedback, config changes, context) — MAX_MEMORY_CHARS=8000
3. fetchSharedNamespaceMemories() → shared namespace recall — MAX_CROSSAGENT_CHARS=2000
4. Cross-agent recall (main → diğer agent'lar) — koşullu
5. fetchDecisionMemories() → decision category recall
6. Operational events: config_change, incident, deployment typed recall
7. Last session summary + daily notes inject
8. Tümü SESSION_CONTEXT bootstrap file olarak inject

### Mevcut realtime-capture handler.js Akışı
1. Message gelir → cleanMessage() ile envelope/metadata strip
2. isCronNoise() + isLowSignal() filtreleme
3. scoreImportance(): base 0.45, decision boost +0.9, feedback boost +0.85
4. User mesajı: decision ise category="decision", feedback ise category="lesson" + feedback tags, diğer category="user"
5. Assistant mesajı: category="assistant", importance=0.5
6. store() → NoldoMem API'ye POST

## Sorun Tanımı

Agent (Claude) tekrarlayan fabrication yapıyor — özellik var/yok iddialarını kaynak koda bakmadan söylüyor, yanlış config bilgisi veriyor, context kaybediyor. Spesifik örnekler:

1. "OpenClaw Brave LLM Context desteklemiyor" → Destekliyormuş, kaynak koda bakmadan söyledi
2. xmcp MCP server önerdi → OpenClaw'da sıfır MCP desteği var
3. "500 fleet pause'ta" → Sadece OpenClaw cron kontrol, crontab/SQLite queue gözden kaçtı
4. Dashboard yanlış şifre seed → Security audit'te değişen şifreyi, eski şifre sanıp seed etti
5. "Ne yapmaya çalışıyordun?" → Context kaybı, memory dosyalarını okumadan sordu

Kök neden analizi: Prompt kuralları epistemik güvenilirlik için zayıf. LLM "varsayım mı yapıyorum?" diye kendini denetleyemiyor. Mevcut sistem post-mortem (hata olduktan sonra yakalıyor) ama prevention (hata olmadan önce önleme) yok.

## Araştırma Bulguları

### Chain-of-Verification (CoVe) — Meta Research (arxiv:2309.11495)
4 aşamalı süreç: Draft response → Doğrulama soruları planla → Her soruyu bağımsız yanıtla → Doğrulanmış final response. Zero-Shot, Few-Shot ve CoT'dan daha iyi sonuç veriyor.

### Anthropic Claude Resmi Dökümantasyonu
- "I don't know" deme izni verme
- Uzun dökümanlardan direct quote extraction (>20K token)
- Citation-based verification: her claim için supporting quote bul, bulamazsan geri çek
- Chain-of-thought verification: adım adım reasoning
- External knowledge restriction: sadece verilen dökümanları kullan

### Letta/MemGPT Agent Memory Mimarisi
- Core memory (her zaman context'te, RAM gibi) + Recall memory (searchable log) + Archival memory (large semantic store)
- Agent kendi memory'sini yönetir, core memory küçük ama kritik bilgileri tutar

### AWS Verified Semantic Cache
- Bilinen sorulara doğrulanmış cevapları cache'le
- Yeni soru geldiğinde önce cache'e bak, cache hit ise LLM'e sormadan dön
- Hallucination'ı bilinen sorular için sıfıra indirir

### Memory Tipleri (CoALA + ICLR 2026 MemAgents)
- Episodic: Spesifik olaylar ("22 Mart'ta Brave LLM Context'i yanlış rapor ettim")
- Semantic: Genel bilgiler ("OpenClaw MCP desteklemiyor")
- Procedural: Nasıl yapılacağı ("Config doğrulama: 1) grep, 2) cat, 3) curl")

### OpenClaw Hook Sistemi — Kritik Bulgu

### Requirement 1: Question-Triggered Mid-Conversation Recall Hook
Yeni hook: message-recall (message:received event'ine bağlı)
- User mesajı geldiğinde, eğer özellik/config/servis/durum sorusu algılanırsa:
- Pattern'ler: "X var mı?", "X destekleniyor mu?", "X çalışıyor mu?", "does X support Y?", "is X running?"
- Mesajdan anahtar kelimeler çıkar (NLP gerekmez, regex + keyword extraction yeterli)
- NoldoMem'den bu anahtar kelimelerle recall yap (lesson + verified_fact + incident kategorileri)
- Sonuçları event.context.bootstrapFiles'a inject ET VEYA event.messages'a uyarı olarak ekle
- Amaç: İlgili lesson tam sorunun sorulduğu anda context'e girsin, bootstrap'teki generic recall'a bağımlı olmasın
- Timeout: max 2 saniye, timeout olursa skip et (response'u bloklamak yok)
- Sadece ilk 500 char'ı al, max 3 sonuç

### Requirement 2: Post-Response Claim Scanner Hook
Yeni hook: claim-scanner (message:sent event'ine bağlı)
- Agent cevabı gönderildikten sonra, response'u tara:
- Negative claim pattern'leri: "desteklemiyor", "yok", "mevcut değil", "not supported", "doesn't have", "doesn't exist"
- Positive claim pattern'leri: "düzelttim", "güncelledim", "tamamlandı", "fixed", "updated N files"
- Config/password/hash claim'leri: hex string, hash, credential referansları
- Her algılanan claim için: aynı session'ın son N mesajında tool call (exec, grep, cat, curl) olup olmadığını kontrol et
- Tool evidence yoksa:
1. NoldoMem'e unverified_claim olarak store et
2. fabrication-log.json'a kayıt ekle
3. Opsiyonel: event.messages'a "⚠️ Bu iddia tool ile doğrulanmadı" uyarısı (configurable)
- NOT: Bu hook response'u ENGELLEMİYOR. Post-mortem audit, ama hızlı — hata pattern'ini yakalar

### Requirement 3: Verified Facts Registry
Yeni dosya: workspace/verified-facts.json + Hook entegrasyonu
- Yapı:

- after-tool-call hook'unu AKTİF ET ve genişlet:
- Tool call'dan sonra eğer sonuç bir feature/config/servis doğrulaması ise, verified-facts.json'a kaydet
- Pattern: grep/find sonucu + "found"/"not found" → fact kayıt
- curl health check → servis durumu fact kayıt
- bootstrap-context'e verified-facts.json loading ekle (küçük dosya, her zaman yüklenebilir)
- Agent "X destekleniyor mu?" sorusuna cevap vermeden önce verified-facts.json'a bakabilir
- TTL: 7 gün default, expired fact'lar "stale" olarak işaretlenir (silinmez, re-verification tetiklenir)

### Requirement 5: Lesson Kategorisi Güçlendirme
